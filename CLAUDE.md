> **Scope:** ONLY rules, invariants and traps invisible at the call site. Not a tour: open the file. Product decisions live in `../claude.md`. When a change makes a rule wrong, fix it in the same commit.

Next.js 16 + Elysia API in `src/app/api/[[...route]]/route.ts`. The Discord bot (`../opencapper-bot`) is a client of this API. Layout, styling and conventions mirror `../../ai-api/unorouter`; when unsure how something is shaped, copy unorouter.

## Rules

- bun for everything. No tests unless asked.
- No dashes as punctuation, no Unicode arrows, curly quotes or ellipsis, no emojis, anywhere.
- Comments only for a non obvious why, one terse line.
- React 19: no `useMemo`/`useCallback`. No destructuring props or hook returns, tuples included.
- Never `as` to silence a type. External JSON is checked with TypeBox `Value.Check`.
- No barrel re-exports. No TS `enum`: TypeBox `t.Union([t.Literal()])` plus derived type (`src/lib/api/typebox/picks.ts`).
- Dates via the dayjs singleton `src/lib/utils/format/date.ts`. Eden revives ISO strings in responses into `Date` objects although the type says `string`: compare with `dayjs(x).valueOf()`, never `localeCompare`.
- Every query key and invalidation goes through `src/lib/react-query/keys.ts`; hooks live in `src/hooks/<domain>/*-hook.ts` on `useElysiaQuery`.
- Translation keys UPPER_SNAKE nested, real translations in every `public/i18n/*.json`, `msg()` for keys outside React. A key list typed as `TranslationKey` widens to the full union and `t()` then demands params: keep literals (`satisfies`, `msg()`).
- Never refactor `src/components/ui/` (shadcn base-ui primitives copied verbatim from unorouter). Only `icon.tsx` differs: lucide only, no icon library switch.
- Dependency direction: `route.ts` -> `*.service.ts` -> db. Domain routers aggregate in `src/server/<domain>/route.ts`. Services throw `ApiError(status, "ERRORS.X", params?)`; no try/catch in handlers. The body is `{ error, code, params? }`: `error` is the English text from `en.json`, the web translates `code` via `apiErrorText`. A new ERRORS message with ICU arguments needs its case in `formatError` (`src/lib/utils/api-error.ts`), or tsc fails.
- Tables use `DataTable` (`src/components/elements/table/`, ported from unorouter, ids in `src/lib/api/typebox/data-table.ts`). The leaderboard passes controlled `sorting`/`pagination` so sort, order, page and size stay in the nuqs URL params and run server side.
- Localized routes go in `pathnames` (`src/i18n/routing.ts`); links use the internal path.
- Roles: Better Auth `admin` plugin, access control in `src/lib/config/permissions.ts` (shared by server and `authClient`). Roles `user`, `moderator` (list and ban users, view picks, imports, system, hide imported profiles), `admin` (also `set-role`, approve and revoke profile claims); no role gets impersonate, create, delete or credential rights. The statement keys `user` and `session` must keep the plugin's names: its own endpoints check them. `ADMIN_USER_IDS` (comma separated Better Auth `user.id`, prod value in Komodo) are admin whatever the stored role. Server checks go through `requirePermission(headers, { ... })` in `src/server/auth/auth.ts` (403 `ERRORS.FORBIDDEN`); `AuthUser.role` is only for showing UI.

## Theme

- Same architecture as unorouter, single scope (no chat/image scopes, wallpaper, saved themes or undo): every knob is a token in `src/lib/theme/tokens.ts` or a preset feeding `generatePalette`; CSS variables are emitted only by `build-css.ts`. Static readers of a token var live in `globals.css`, which also holds the base values and the default fonts on `body`.
- The theme lives in the `user-theme` cookie (`v: 2`); `migrateTheme` runs on every read. The locale layout reads it and bakes `buildThemeCss` into `<style id="user-theme">` plus the `googleFontHref` link for a custom Google font. `userThemeAtom` (`getOnInit: true`) is PAIRED with `UserThemeStoreProvider`: without the seed, `UserThemeProvider`'s effect overwrites the baked style with default CSS on first render. Removing either half breaks it.
- Editor: `/settings/appearance` (`src/components/elements/theme/`, `use-theme-editor-hook.ts`). Font tokens write on `body` with `!important` because the defaults sit there.
- The default look is the `cinematic` palette and style presets in `INITIAL_USER_THEME`: monochrome, no accent, translucent hairlines from the palette's `overrides`. Colour only appears as `pick-*` accents. Dark is the default mode (next-themes `defaultTheme` and the inline head script both treat an unset theme as dark).
- Pick status colours are the `pick-*` tokens (`bg-pick-win/15 text-pick-win`); never raw green or red for a result, and never a win amount in an accent coloured button or banner.
- Fonts: Google Fonts via `next/font/google` only, in `src/lib/theme/fonts.ts` (Geist body and display, Geist Mono numbers; the rest are picker options, preload off). Geist Pixel (Square cut) is `font-pixel`. No font files in the repo. Every stat, odds, units, ROI and numeric table cell uses the `tabular` utility.
- Registries feeding `t(key)` type their keys as `PlainTranslationKey` (no ICU args), or `t` demands params.
- No copied third party code or assets: write our own. `line-field-bg.tsx` is a canvas 2D field that only draws at `lg`, clears behind `[data-line-field-clear]` and draws a single frame under reduced motion.
- Ranking thresholds and proof marker style are runtime env (`serverEnv.ranking`, defaults in `src/lib/config/ranking.ts`), passed from server pages as props.

## Invariants

- Picks are append only. No update or delete route except grading `result`. Migration `0001_picks_append_only.sql` enforces it with a trigger (UPDATE may only change `result`; DELETE and TRUNCATE raise), tightened in `0019_result_guard.sql`: `result` may leave `pending` freely, but a final result changes only through `correctResult` (`grading.service.ts`), which writes an append only `pick_result_changes` row in the same transaction (the trigger matches it on `txid_current()`). Never drop either; a schema change that touches `picks` must keep them.
- Grading writes only `picks.result`; scores, `graded_at`, closing price, CLV and `void_reason` live in `pick_settlements`. The job (`src/server/grading/grading.job.ts`, started from `instrumentation.ts`) spends Odds API credits on every tick: keep calls grouped per sport (scores) and per event (closing odds). An Odds API pick is never voided silently: past the 3 day scores window its sport is polled every 6 hours with a structured `grading_overdue` log, voided `postponed` only when the feed moved the game 48 hours or more, and `timeout` after 30 days (`grading_void_timeout`); admin system shows the backlog.
- Results (`src/lib/config/results.ts` is the one place their money lives): `half_win` and `half_loss` are quarter lines (half the stake on each neighbouring half line), `split` is a Polymarket 50/50 resolution (0.5 paid per share, half win plus half loss). Records count them as win, loss and push; every stake that was at risk counts in ROI. Legacy `history_picks` rows store a 50/50 as `void` and are read as `split` (`historyResult`); history never voids otherwise.
- Picks locked at or after the real start get an append only `pick_disqualifications` row (importer cross check, grader when the feed or gamma shows an earlier start, or `scripts/repair-grading.ts`). The pick stays listed with `disqualified`, and every record, ROI and graded count leaves it out through `countedPick` (`stats.service.ts`); a new aggregate over `picks` must filter on it.
- The server captures odds; a caller never supplies a price. A pick for an event that has started is rejected. The one exception is `exchangeFill` in `CreatePickInput` (bookmaker `polymarket`): the on chain fill price of an imported Polymarket trade, set only by `src/server/importers/`, never reachable from a route. It still rejects started events and fills after the start, and its `pick_sources` row links the transaction. The importer takes the earliest of gamma's event `startTime`, market `gameStartTime` and the free Odds API `/events` start (`listEventStarts`, which keeps games in play), rejects gamma `live` or `ended` events, and prices the pick at the size weighted average of the pre start fills that make up its units.
- Imported picks: `pick_sources` (one row per pick, append only trigger in `0010`) holds the source link, the original post time and the dedupe key; `picks` and `canonicalPick` are unchanged. Platform time is the import time, never the post time. Polymarket picks grade on the market resolution (`gradeExchangePicks`), never on redemptions: losing positions are mostly never redeemed. Odds API grading and closing capture skip bookmaker `polymarket`.
- On chain history (`history_picks`, append only trigger in `0012`) is never a pick: resolved Polymarket taker BUYs from before the event start, backfilled once at startup (`IMPORT_POLYMARKET_HISTORY_DAYS`, needs the Polymarket importer on). Never write them into `picks` or `pick_log`, never label them as live. A pick key already in `pick_sources` is skipped, so a game never counts twice. The leaderboard ranks live plus history by default and must keep the per row split and the live only scope; profiles show history in its own tab.
- Every pick is chained into `pick_log` inside the `createPick` transaction (`appendPick`, advisory lock, `root = sha256(prev_root || leaf)`, genesis 32 zero bytes). Migration `0006_pick_log_append_only.sql` rejects UPDATE, DELETE, TRUNCATE and any INSERT that does not extend the chain. The leaf is the sha256 of `canonicalPick`: changing its fields or key order breaks every published root, so never touch it. `backfillLog` logs picks that missed the log.
- `log_anchors` gets one OpenTimestamps proof a day from the instrumentation timer (`startLogAnchoring`); each calendar branch has its own nonce so the stored `.ots` needs no merge. Rows only allow updating `ots` and `upgraded`.
- Sequence numbers are per user and gapless: `createPick` locks the user row before `max(sequence) + 1`.
- Profile claims (`profile_claims`, `src/server/claims/`) only link an imported profile to the claimant's own `users` row. A claim never moves, rewrites or re-attributes picks, `pick_log`, `pick_sources` or `history_picks`, and never sets the imported row's `auth_user_id`. One active claim per profile (partial unique index on `revoked_at is null`); revoking sets `revoked_at`. Proof is a one time code in the source bio (gamma `public-profile` `bio`, Reddit `about` via the OAuth API); without Reddit credentials Reddit claims are manual, admin only.
- Hidden profiles (`users.hidden_at`, imported profiles only, set by the claimant or staff) are excluded everywhere a person is listed or looked up by name: leaderboard (both tables, so the landing top cappers and dash too), landing ticker, `/api/users/:username/*` (empty), profile stats (zeroed, no source, picture or claim), metadata (noindex), OG profile and pick cards (brand card), `/api/log/users/:username/:seq`, claimed profile back links, the capper check (`/api/check`, no match) and the record badge (neutral "no record"). Lookup by pick id and the log export stay, the pick log is never filtered. Importers skip them: `createPick` rejects a hidden source identity (`ERRORS.PROFILE_HIDDEN`) before spending credits, the Polymarket importer, history backfill, image refresh and Reddit importer filter them up front. New public listings must filter on `visibleUser` (`src/server/users/hidden.ts`).
- Capper payments (`src/server/payments/`, Whop connected accounts, off unless `WHOP_API_KEY` and `WHOP_WEBHOOK_SECRET` are set): access decisions read only `subscriptions` (provider neutral), never a provider API. Only signed up, visible users with `MIN_GRADED_PICKS_TO_SELL` graded live picks may connect or set a plan. The onboarding link is a bearer URL: return it to its owner, never log or store it. The webhook (`POST /api/payments/webhooks/whop`, `parse: "none"`) verifies the raw body, stores the event in `payment_events` (unique per provider and event id) and upserts the subscription in the same transaction, so a failure rolls back and Whop retries; `provider_updated_at` keeps a late older event from overwriting a newer state. Memberships map to a buyer and capper through the checkout `metadata` (`buyer_user_id`, `capper_user_id`), and count only when the membership's account (and product, once stored) matches that capper's stored Whop ids. `payment_events.payload` holds an allow listed minimum (`whop.events.ts`: ids, type, status, amounts, fees, currency, period, timestamps), never the raw body. Sellers must be unbanned and still eligible at checkout. Checkout variants are hidden and carry no metadata, so Whop reuses a matching variant. A single member TypeBox union collapses to its literal, so `PaymentProvider` is a `t.Literal` until a second provider lands.

## Traps

- API contract is mirrored by hand in `../opencapper-bot/src/lib/api.ts` and its README. Change both repos together. `error` messages are shown to Discord and Telegram users verbatim, so ERRORS values in `en.json` must read as sentences. `ApiError` keeps its key on `key`, never `code`: Elysia treats `error.code` as its own error kind and skips the ApiError branch.
- Capper check (`src/server/check/`, page `/check?q=`): `GET /api/check?q=` resolves one free text query (OpenCapper username, Discord id or lowercased name, Telegram slug, `pm_`/`rd_` import slug, source handle such as a wallet, a pasted profile link) to at most 5 visible profiles, best match first; `GET /api/check/discord/:discordId` matches the Discord id only, which the bot's `/capper user` uses so a same named account never answers for a mention. Never select or return emails there. Both are public and rate limited in process per IP (`src/server/rate-limit.ts`, `cf-connecting-ip` then `x-forwarded-for`); the bot token skips the limit, and the page's server prefetch forwards the viewer's IP headers or every SSR lookup would share one bucket. `GET /api/ops/badge/:username` (optional `.svg`) is a monochrome SVG of the combined live plus history record, cached 5 minutes; unknown, invalid or hidden names get the neutral badge with a 60 second cache, never a JSON error.
- `GET /api/leaderboard`: `sport` is one sport group or a comma list (`mma,boxing`), `sort` is `roi`, `units`, `picks`, `rank`, `capper`, `record` (win rate, then wins), `sports` (count) or `last` (latest locked or traded pick), and rows carry `lastPickAt`. The nuqs parsers live in `*-params.ts` (`nuqs/server`) so the server prefetch builds the client's exact query key; keep both in that one file.
- Pages prefetch every query their first render uses through `prefetchElysia` (`src/lib/react-query/prefetch.ts`, in process `treaty(app)` with the viewer's cookie) and wrap the client tree in `HydrationBoundary`. Data now renders on the server, so a client component that formats a date must pass `useHydrated()` as the formatter's `local` flag (UTC until hydration) or React hydrates against the server's time zone and throws a mismatch.
- Profiles key on `users.username` (lowercased, unique). Discord rows keep the lowercased Discord name and follow renames only into a free name; Telegram and Google rows get a slug, with `_xxxx` appended on collision (`src/server/users/identity.service.ts`). Never rename to resolve a collision. Telegram chats live in `picks.guild_id` as `tg:<chatId>`, so recap and settled feeds need no new column.
- Web session: Better Auth (`src/server/auth/auth.ts`, handler at `src/app/api/auth/[...all]/route.ts`, which wins over the Elysia catch all). `BETTER_AUTH_SECRET` >= 32; rotating it logs everyone out. Discord redirect URI is `<site>/api/auth/callback/discord`. Default scopes (`identify`, `email`), so `user.email` is the real Discord email. Its `mapProfileToUser` upserts the domain `users` row on every sign in. `getAuthUser` resolves by `users.auth_user_id`, then a linked Discord (preferred) or Telegram account, then creates a row (Google), and stores `auth_user_id`. Google is optional (`GOOGLE_CLIENT_*`); Telegram is the `telegramAuth` plugin (`/api/auth/telegram/sign-in`, widget HMAC check, synthetic `<id>@telegram.invalid` email; a signed in caller gets Telegram linked to their user). Account linking trusts discord, google, telegram by verified email. Never add Better Auth `additionalFields` with `input: true` for identity: `/api/auth/update-user` lets the client set them. "Am I logged in" is the `auth` query seeded by `prefetchAuth` in the navbar layout (user or explicit `null`), never a cookie check.
- `/api/auth/admin/*` (set role, ban, unban, list users) is the plugin's, not ours; `/api/admin/*` (Elysia, `src/server/admin/`) reads, plus hide and unhide (`profiles: ["hide"]`) and claim approval and revocation (`claims`) of imported profiles. `guardAdminEndpoints` in `auth.ts` refuses banning yourself or an admin and every impersonation, since the plugin allows both. A ban lives on the Better Auth user: the plugin deletes its sessions and blocks sign in, and `createPick` rejects banned callers (`ERRORS.USER_BANNED`) before spending credits. A Discord or Telegram bot identity that never signed in on the web has no Better Auth user and cannot be banned. `/admin` answers 404 to anyone below moderator.
- OG images: `src/server/ops/og/` (satori to SVG, sharp to PNG, `GET /api/ops/og/:template`). App routes may not import `react-dom/server`, so icons are path data in `lib/icons.ts`. Fonts are the `@fontsource/geist` and `@fontsource/geist-mono` woff files (satori cannot read woff2), read from `node_modules` (`.next/node_modules` inside the binary) at runtime and shipped by `outputFileTracingIncludes`; after touching either, curl every template inside the Docker image. A template that throws falls back to the brand card with a 60 second cache. Geist has no kana or kanji: `fontsFor` adds the `@fontsource/noto-sans-jp` 400 subsets only for `ja`.
- `getDb()` is lazy: `next build` imports route modules without `DATABASE_URL`. Never touch the DB at module scope.
- Migrations run from `src/instrumentation.ts` and read `drizzle/` from disk; `outputFileTracingIncludes` is what ships that folder inside the compiled binary.
- Custom SQL migrations: `bunx drizzle-kit generate --custom --name <name>`, never hand-edit `drizzle/meta`. Schema lives in `src/lib/db/schema/server.ts`.
- `next.config.ts` sets `typescript.ignoreBuildErrors`; `bun typecheck` is the gate. After moving files or editing `en.json`, a stale `tsconfig.tsbuildinfo` or `public/i18n/en.d.json.ts` reports phantom errors: delete it and rebuild.
- `next build` refuses every second run when it detects a coding agent; rerun once.
- Komodo: the app service needs `env_file: .env` or it gets no runtime env. Healthchecks use `127.0.0.1`, not `localhost`. Network `proxy` is external and must exist. Distroless has no shell; the image carries busybox as `wget` for the healthcheck only. `GIT_SHA` reaches the build as an arg (default `dev`, Komodo passes none); the build stamps `deploymentId` with it or, for `dev`, a timestamp, so asset URLs change every deploy. During a container swap Traefik answers its own uncached `404 page not found`, which Cloudflare caches: a constant `deploymentId` lets that 404 poison a chunk URL across deploys. Never push twice within a build window.
- Legal pages (`src/components/pages/legal/`, `/impressum`, `/privacy`, `/terms`): the operator's name, address, VAT ID and contact email come only from the `LEGAL_NAME`, `LEGAL_ADDRESS` (lines joined by a literal `\n`), `LEGAL_VAT_ID` and `LEGAL_EMAIL` stack env in Komodo, which compose passes as `NEXT_PUBLIC_LEGAL_*` build args; they are inlined at build time, never committed, and the Dockerfile stops the build when one is empty. Changing them needs a rebuild, not a restart. Their texts live in the `LEGAL` namespace, which the locale layout strips from the client messages, so legal components stay server components. Any change to what the app stores, sends to a third party or sets as a cookie must update the privacy texts in all locales and `LEGAL_UPDATED`.
- TheSportsDB (participant images) answers 429 after 12 to 15 searches a minute on the free key (measured, not the documented 30) and then locks out for about 100 seconds (`Retry-After`). The queue spaces calls 6 seconds apart and pauses on `Retry-After`; a 429 is never cached, so a faster queue only refills a few logos per page view. Request paths read the `participants` cache via `lookupParticipants`, which refreshes misses in the background, and the pick board reports `imagesPending` so the client polls until they land. Never await TheSportsDB in a request.
- Importers share one daily Odds API budget (`IMPORT_ODDS_CREDITS_PER_DAY`, default 0) and one odds call per event per cycle (`createCycle`); never call `fetchEventOdds` from an importer outside `cycle.loadOdds`.
- Reddit's Data API terms need Reddit's written approval for commercial use; get it before enabling the Reddit importer in production. Use the OAuth API only: the public JSON is blocked from datacenter IPs.
- Avatars resolve in one place, `avatarUrl` (`src/server/users/avatar.ts`): the Discord hash, then `users.image_url` (imported profiles; Polymarket pictures refresh daily from the gamma `public-profile`), then the Better Auth `image` (Google, Telegram), so queries left join `authUser`. No picture renders the username gradient in `CapperAvatar`.
- Imported profiles (`users.source_platform` set) have no auth link, claimed or not. The UI must never imply they signed up: no verified badge, the "public" badge and the source banner instead; a claim only adds "Claimed by @name". The removal link mails `NEXT_PUBLIC_LEGAL_EMAIL`, else the Discord invite.
- Every ICU `select` in `en.json` multiplies the cost of the typed message keys; a few more push tsc into TS2590 ("union type too complex"). Pass brand names as a plain `{platform}` argument (`SOURCE_NAMES`) instead of adding selects.
- The Odds API bills per region times market; `captureOdds` asks for `us,eu` and one market. `/events` is free. `getEventLines` (web pick form) asks for all three markets and is cached 60 seconds in process; never use its cached price for a pick.
- Pick board (`src/server/odds/board.service.ts`, `GET /api/events/board`): events from the free `/events` list plus one `/sports/{sport}/odds` h2h `us,eu` call per league (2 credits) cached 15 minutes in module state, under `BOARD_ODDS_CREDITS_PER_DAY` (default 20). Past the budget the last prices stay up with their age; without them the board lists events unpriced. Only `PICK_LEAGUES` keys are accepted, so a crawler cannot spend credits on arbitrary sport keys. Worst case without the budget is 2 x 96 = 192 credits per league per day. The board price is indicative only and never reaches `createPick`. The in season filter (`/api/events/leagues`) reads the free `/sports` list, cached 6 hours.
- Landing data (`src/server/landing/landing.service.ts`): the showcase pool is `getFeaturedEvents` (board service): big leagues starting within 72 hours, ranked by how many bookmakers quote the game (our popularity signal), priced from the board's budgeted league cache, so the landing page spends no credits of its own. The client starts at a random game and rotates. Without prices it falls back to the next event from the free `/events` list, unpriced. DB stats are cached 60 seconds. Every source degrades to null; the page never throws on a missing key or DB.
